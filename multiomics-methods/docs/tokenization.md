# 토큰화 — 조성 자료를 시퀀스로 보기

`mox.tokenize` 는 다른 모듈과 관점이 다릅니다. 나머지가 "표본 × feature 행렬"을
다루는 데 반해, 여기는 표본 하나를 **토큰 시퀀스**로 봅니다. 트랜스포머에
넣으려면 그 변환이 필요하고, 그 변환에서 무엇을 버리는지가 설계 결정입니다.

## 값 인코딩 세 가지

단일세포 파운데이션 모델들이 쓰는 방식을 그대로 옮겼습니다.

| 모드 | 방식 | 버리는 것 | 출처 계열 |
|---|---|---|---|
| `rank` | 풍부도 내림차순 순위만 | 절대값 전부 | Geneformer |
| `bin` | CLR 값을 분위수 구간으로 이산화 | 구간 내 해상도 | scGPT |
| `cont` | CLR 값을 연속값 그대로 | (없음) | scFoundation |

**`rank` 의 거래.** 순위만 남기면 배치효과에 강해집니다. 배치가 값을 통째로
이동시켜도 순서는 잘 안 변하기 때문입니다. 대신 "얼마나 많은가"를 통째로
잃습니다. 의도된 손실이지만 손실입니다.

**`bin` 의 함정.** 구간 경계를 전체 자료의 분위수로 정하면, held-out 표본의
분포 정보가 경계를 통해 새어 들어옵니다. 그래서 `ValueEncoder` 가 함수가
아니라 fit/transform 객체입니다. **fit 은 train fold 에서만.**

`tests/test_tokenize.py::test_value_encoder_bins_are_learned_on_train_only`
가 이걸 붙잡습니다.

## 어느 모드든 CLR 이 먼저

조성 자료의 폐쇄성(합=1)을 풀지 않으면 "하나가 늘면 나머지가 준다"는 가짜
음의 상관이 그대로 모델에 들어갑니다. 순위를 매기든 구간을 자르든, CLR 이후에
합니다.

```
상대풍부도 → pseudocount → CLR → 순위/구간/연속
```

## 계통수를 어텐션 제약으로

분류군은 독립 항목이 아니라 계통수 위에 놓여 있습니다. 완전연결 어텐션은 그
구조를 무시한 채 L² 개의 쌍을 전부 추정합니다. 표본이 적을수록 손해입니다.

계통상 가까운 분류군끼리만 어텐션을 허용하면 추정할 자유도가 줄고, 계산량이
줄고, 사전지식이 모델에 들어갑니다.

```python
A = lineage_adjacency(lineage_df, feature_names, level="family")
mask = attention_mask(ids, A)          # (N, L, L) 불리언, True = 허용
# torch 로:  bias = torch.where(torch.as_tensor(mask), 0.0, float("-inf"))
```

**level 이 하이퍼파라미터입니다.** 낮출수록(genus) 마스크가 촘촘해지고
높일수록(phylum) 완전연결에 가까워집니다. `sparsity(A)` 로 밀도를 확인하세요.
1.0 이면 완전연결과 같아 제약이 없는 것이고, 너무 낮으면 정보가 흐르지
못합니다.

**완전히 막힌 행이 생기면 softmax 가 NaN 이 됩니다.** `attention_mask` 는
자기 자신과 패딩 행을 항상 열어 둡니다.
`tests/test_tokenize.py::test_attention_mask_never_fully_blocks_a_row` 가
가장 촘촘한 마스크(단위행렬)에서도 이게 지켜지는지 확인합니다.

**계통 정보가 없는 feature 는 자기 자신하고만 연결됩니다.** 정보 없는 것들을
한 덩어리로 묶으면 "미상"이라는 가짜 분류군이 생기기 때문입니다.

## torch 를 쓰지 않습니다

이 모듈은 numpy 만 씁니다. 여기서 나온 배열을 텐서로 감싸면 됩니다.
방법론 패키지에 학습 프레임워크 의존성을 넣지 않으려는 것이고, 덕분에
토큰화 로직 자체를 가볍게 테스트할 수 있습니다.

트랜스포머 학습 코드(마스킹 복원 사전학습, 모달리티 간 대조학습)는 이
저장소에 없습니다. 그건 방법론이 아니라 실험이고, 여기 옮겨 오면 검증하지
못한 코드가 패키지에 들어가게 됩니다.
