# 결측 — 메우기 전에 왜 비었는지부터

## 기전이 다르면 처리도 다릅니다

오믹스 자료의 결측은 최소 세 종류가 섞여 있고, 하나로 처리하면 반드시 어느
쪽을 망칩니다.

| 기전 | 신호 | 맞는 처리 |
|---|---|---|
| 무작위 결측 | 흩어져 있고 값의 크기와 무관 | 중앙값 대치로 충분 |
| 검출한계(LOD) | 결측률과 평균값이 **음의 상관** | 좌측중도절단 대치 |
| 표본/배치 실패 | 특정 표본·피험자에 결측이 몰림 | 대치하지 말고 제외 |

`mox.qc.report()` 가 세 가지를 구분해 줍니다. 파이프라인을 돌리기 전에 한 번
찍어 보라고 만든 것입니다.

## 왜 중앙값 대치가 검출한계에서 틀리는가

검출한계 결측은 "값이 낮아서" 안 보인 것입니다. 그 자리에 중앙값을 넣으면
실제로는 낮은 값을 **위로 끌어올립니다**. 낮게 발현되는 feature 일수록 결측이
많으니, 편향은 하필 가장 낮은 feature 들에 집중됩니다.

합성 자료는 참 LOD 를 알기 때문에 편향을 직접 잴 수 있습니다
(`scripts/run_missing_data.py`, 시드 0, 참 LOD = −1.50).

| 대치 방식 | 대치 개수 | 평균 대치값 | LOD 대비 편향 |
|---|---|---|---|
| 모든 블록 중앙값 | 631 | −0.428 | **+1.072** |
| 기전별 (5% 분위수) | 631 | −1.266 | +0.234 |
| 실제 LOD 값 사용 | 631 | −1.500 | **0.000** |

중앙값 대치는 참값보다 평균 1.07 (NPX 단위) 위에 채웁니다. 분위수 근사가
그걸 4.6배 줄이고, 실제 LOD 를 넘기면 0 이 됩니다.

**LOD 값이 있으면 분위수로 근사하지 마세요.** Olink 처럼 LOD 가 함께
배포되는 자료라면 `BlockPrep(..., lod=lod_vector)` 로 넘기면 됩니다.
분위수 근사는 관측된 값들의 분위수라 정의상 LOD 위에 있습니다 — 위 표에서
기전별 방식의 `frac_above_lod` 가 여전히 1.00 인 이유입니다.

## 대치로는 고칠 수 없는 결측

표본이나 피험자 단위로 블록이 통째로 비어 있으면 대치할 근거가 없습니다.
그런데도 메우면, 그 표본은 **"가장 평균적인 표본"** 이 되어 군집 한가운데로
끌려갑니다. 그 위치는 자료가 아니라 대치가 정한 것입니다.

합성 자료에는 피험자 2명이 4회 방문 내내 대사체의 27% / 73% 가 비도록 넣어
두었습니다(실제 코호트 자료에서 관찰한 모양). 대사체 PCA 공간에서 중심까지
거리의 백분위를 재면:

| 처리 | 결측 피험자 | 나머지 |
|---|---|---|
| 모든 블록 중앙값 | **1.3 퍼센타일** | 51.3 |
| 기전별 대치 | **1.3 퍼센타일** | 51.3 |
| 기전별 + 표본 제외 | (제외됨) | — |

**대치 방식을 바꿔도 전혀 나아지지 않습니다.** 이 결측은 검출한계가 아니라
검체/배치 실패라서, 대치를 정교하게 하는 것으로는 해결되지 않습니다.
표본을 빼야 합니다.

기전을 먼저 보라는 말의 뜻이 이것입니다. 처리 방법을 고르기 전에 진단이
와야 합니다.

## 실무 순서

```python
from mox import qc
print(qc.report(blocks, md))              # 1. 기전을 본다
flag = qc.flag_incomplete(blocks, md, 0.20)   # 2. 못 쓰는 표본을 가려낸다
# 3. 남은 것에 기전에 맞는 대치를 건다 (BlockPrep 의 블록별 기본값)
```

`mox` 의 블록별 기본 대치는 이렇게 되어 있습니다.

| kind | 기본 대치 | 이유 |
|---|---|---|
| `compositional` | median | 0 은 결측이 아니라 관측된 부재. pseudocount 로 처리 |
| `intensity` | median | 대사체 결측은 보통 값과 무관 |
| `log_abundance` | **left_censored** | NPX 의 below-LOD 가 기본 기전 |

기본값이 맞지 않으면 `na_strategy=` 로 바꾸세요. 다만 바꾸기 전에
`qc.censoring_report()` 를 한 번 보시길 권합니다.
